# 链接自动读取：第四轮开源研究与云端试验

测试日期：2026-09-21。目标保持“用户粘贴链接，云端自动读取”，不把用户上传素材改作主要入口。本轮零付费模型调用、零充值、零媒体下载；没有复制个人 Cookie、登录共享、代理轮换、破解签名或跳过访问门禁。

## 结论与实施范围

- 找到一个此前未接入的抖音官方公开摘要入口。3 个固定作品在本机和杭州 ECS 均取得匹配原始作品 ID 的 `abstract`，两环境摘要 SHA-256 完全一致。
- 这些数据是 **公开摘要，不是完整原始文案，更不是视频口播**。不能用这 3 个固定作品证明新链接 95% 可读、全量视频可分析或真实准确率。
- 新版解析器 3.4 对明确的抖音视频路由优先选择该公开入口；短链正常跳到视频 ID 后适用。图文、slides 和只有 `modal_id` 的模糊地址不擅自转换。
- 严格校验 SSR 指定位置的字符串 `gid`，只接受非空字符串 `abstract`，永远返回 `metadata_only / partial`，媒体列表为空。解析、登录、验证或 HTTP 拒绝后不切换其他入口继续抓取。
- 小红书本轮没有取得改善：新开源实现的首条控制样本进入登录/验证跳转，剩余 2 条未执行。不是 3 条全失败，也不能把历史成功样本当本轮效果。
- ECS 是独立只读试验，未修改其常驻读取器或生产连接。网站自身发布后的验证另行记录，不能拿 ECS 成功代替。

## 第三方服务不是直接可上线的答案

TikHub 有 [小红书按 ID/分享文本读取接口](https://docs.tikhub.io/420136391e0)，但是自选链接测试需要测试 Key，本轮没有开户或充值。固定免费示例不能用于成功率验收。

根据其 [使用条款](https://docs.tikhub.io/9453286m0) 的 §3/3.1，需要先确认面向终端用户的产品集成是否获准；§1.3 不保证其访问方式已获源平台授权，§8.6 要求客户对中国平台数据下游使用负责。[业务限制](https://docs.tikhub.io/5448547m0) 是商家准入说明，不能误称“中国大陆用户或杭州 ECS 一概被禁用”，也不能据此推定商用已授权。

后续商业化验证的输入条件：供应商确认该终端用户场景可用、允许的保存/展示/分析范围、来源授权与处理地域，以及专用于本项目的试用 Key。然后冻结新样本，分别统计正文、媒体、摘要、门禁与错误身份，不只统计 HTTP 200。未满足这些条件，不将收费接口接入公共网站。
