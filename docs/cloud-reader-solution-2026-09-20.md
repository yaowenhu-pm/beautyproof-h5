# 云端读取完整解决方案与 20 条验收计划

## 目标及不可省略的验收条件

保留现有产品网址，让外部用户提交小红书/抖音链接时，由云服务器读取对应公开作品，再交给现有证据分析流程。本轮先验收内容获取，模型付费调用为 0，不改变已有 1 元分析总预算。

固定 20 个不同作品（小红书 10、抖音 10），包含历史失败样本和新候选，测试前锁定清单；失败样本不删除、不用新的成功样本替换。只有读到非空正文、作品身份一致且内容来源可核对，才算正文读取成功。HTTP 200、识别作品 ID、只有标题、搜索摘要、登录/校验页及人工预置正文均不算通过。视频说明文案不等于视频口播。目标是 20/20 正文通过；达不到则明确不满足该目标，记录真实原因，不承诺平台永久可用。

## 已知问题与架构调整

上一轮 ECS 主动访问现有站点被 Cloudflare 返回 403。因此不继续让 ECS 轮询该站点，也不通过代理池或关闭验证回避风控。改成正常的反向调用关系：

外部用户 → 现有网站 `/api/resolve` → HTTPS、签名验证 → ECS 只读接口 → 平台公开页面 → 校验作品和正文 → 原路返回。

这样不迁移网页、分析模型和预算账本，也不把接口签名私钥放到浏览器。ECS 的公网仅开放：443 提供受签名保护的读取接口；80 仅用于 ACME 免费证书校验，其余路径拒绝。SSH、远程桌面、Chrome 调试/CDP 等不对公网开放。新增网络暴露及证书协议在实施前取得用户明确同意。证书自动更新免费，与服务器付费自动续费无关；ECS 保持手动续费。

优先使用用户已有子域名；没有时可使用 sslip.io/nip.io 的临时演示域名解析到当前 ECS，申请独立有效的 HTTPS 证书，不能依赖自签名证书或关闭校验。临时 DNS 属于第三方依赖，仅适合演示；正式推广应换为自有域名。Cloudflare Workers 的普通 fetch 不支持直接以 IP 为目标，因此不能把裸 IP 证书视为现有网站接入的充分条件。

## 服务端实现

- Node 只读服务监听 127.0.0.1；Nginx 终止 HTTPS，只转发 `/v1/resolve`，健康检查不暴露凭据和内部配置。
- 请求采用 Ed25519 签名、短时间窗、随机 nonce 和 requestId，限制请求体大小/读取时间，拒绝重放。Sites 保管专用签名私钥，ECS 仅保存公钥。
- 网站及 ECS 分别限流；浏览器单并发、有限排队；相同 URL 合并进行中的请求，完整 URL（含分享参数）参与缓存键。成功缓存 5 分钟、失败 10 秒，不永久缓存旧正文。
- 限制总执行时间，失败不自动收费重试；网络、超时、平台限制与作品删除分别返回明确状态。
- 目标必须是已支持的平台 HTTPS 域名；每一跳检查域名和作品 ID，拒绝内网/metadata/任意跳转。媒体地址只列出，不在本轮下载或转发。
- 系统服务使用独立非 root 用户，启用进程重启和日志上限。日志只记录请求 ID、状态、耗时，不写 Cookie、分享参数、正文或模型密钥。
- 上轮未发布的轮询队列作为关闭的实验路径保留，本次默认不启用，不让两条读取路径重复抓取。

## 读取策略

1. 链接规范化保留平台必须的签名参数；解析分享文本，拒绝多条作品混在同一次输入。
2. 小红书对可匿名公开的页面先用已有 HTML 解析；门禁即停止，不能将 App 引导页当正文。
3. 抖音等正常依赖 JavaScript 渲染的公开页面使用官方 Playwright/Chromium 普通浏览器路径；不使用 stealth、指纹伪造、签名逆向、代理轮换或验证码绕过。
4. 浏览器使用独立匿名上下文，启用沙箱，不复用本地个人 profile，不操作评论、关注、点赞、发布或下载。每个任务只打开目标作品，读取正常展示的内容。
5. 浏览器采集同时检查当前作品 ID、初始化状态与可见正文；推荐流、其他作品和搜索摘要不得冒充目标内容。
6. 遇到明确登录/验证/私密/删除/地区或 App 限制，停止任务并返回限制。若需要账号，必须另行确认平台授权与专用账号用途，再由用户完成登录；用户个人登录态不默认变成公共抓取能力。

## 测试与发布顺序

1. 锁定 20 条候选，记录发现来源、作品 ID、平台、话题和初始状态。
2. 免费离线测试：链接身份关联、门禁识别、URL 白名单、签名篡改/过期/重放、慢请求和大请求、限流、排队与缓存隔离；不得调用分析模型。
3. ECS 独立测试：先 2 条正向与已知失败各 1 条，再按锁定顺序完成 20 条；请求低频执行，碰到平台门禁不自动重试。
4. 网站接口契约测试：由当前站点真正调用 ECS，校验返回 requestId/sourceUrl/内容一致；伪签名应被拒绝，不从浏览器暴露凭证。
5. 20 条从真实网站入口逐条复验，记录正文长度、媒体链接数量、读取方法、耗时、原因、时间；另测重复输入缓存和 A/B 内容不串线。
6. 若出现故障，只针对原因修复；保留首轮和复测记录，不能覆盖失败历史。20/20 未达到时报告为未通过，而不是重新定义“没问题”。
7. 仅发布构建与安全检查通过的版本，保留旧版本供回滚；新增环境变量关闭即可恢复原读取策略。GitHub 同步代码，但绝不提交密钥、个人会话、服务器证书或浏览器资料。

## 交付清单

可用的云端读取服务（或明确的阻断状态）、现有站点接入结果、20 条逐条实测表、失败原因与后续必要授权、离线测试记录、部署/停止/回滚说明，以及费用记录。不得把“代码写完”“服务器单测成功”当作“公开网站端到端成功”。
