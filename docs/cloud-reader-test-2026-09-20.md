## 网站接入的实际阻断

- 从 ECS 请求现有站点首页和 `/api/resolve`，收到 Cloudflare HTTP 403，页面标题 `Attention Required! | Cloudflare`，没有进入应用正常 JSON 响应。
- 同时 ECS 访问 GitHub 原始源码返回 HTTP 200，不能把该故障归因于服务器完全断网。
- 本地电脑不带登录凭据访问现有站点首页返回 200、正确标题；向 `/api/resolve` 提交空 JSON 返回应用预期的 400 参数错误。这里未提交分析，不消耗模型额度。
- 可以确认是 ECS→当前托管入口的访问被拦截；仅凭响应不能确定是 IP、地区还是其他风控规则。未绕过验证，也未关闭安全保护。

因此本轮**没有**启用队列公钥环境变量、生成生产私钥、应用生产数据库迁移、发布新版本或把现有用户流量切到 ECS。网站保留原发布版本，不能将“服务器脚本成功”描述为“用户已可使用云端服务”。

## 本地已准备但未发布的接入代码

网站侧新增签名工作队列、原子限流、短期缓存、单任务 claimToken、请求体大小/时间限制、结果与源作品校验。独立 Node worker 通过固定 HTTPS 地址领取任务，不需要对 ECS 开放入站端口，不包含模型密钥或个人 Cookie。成功缓存 5 分钟、失败缓存 10 秒，错误结果不伪装成正文。

离线验证：56 条链接回归、31 条 V2 回归、现有 6 组规则样例、读取协议回归、worker 源码及单文件各 15 项测试均通过；TypeScript 检查和生产构建通过。Sites 构建辅助脚本遇到本机 npm 路径问题，改用项目原有 `npm run build` 成功。未宣称端到端队列验收通过。

1. 先通过托管平台支持/允许的网络配置解决 ECS→Sites 的 403；如不能放行，再确认将前后端统一迁移到可控部署环境和正式 HTTPS 入口，不能擅自把生产接口降为明文 HTTP。
